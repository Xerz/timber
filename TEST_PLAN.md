# План тестирования (Tauri + macOS)

**Цель**
Проверить корректность логики и UI на macOS и вручную подтвердить Windows‑специфичную часть (реестр, запуск exe).

**Инструменты**
- Node.js 20+.
- `node --test` для unit/интеграционных тестов.
- Playwright (Chromium) для UI‑скриншотов и hover.

**Unit‑тесты (JS, macOS)**
1. Фильтрация игр `enabled` (+ `verified == READY`, если поле есть).
2. Маппинг карточек (title, image, badges).
3. Правила “Бесплатная”.
4. Использование `game_path/work_path/args` из списка игр.

**Интеграционные тесты (JS, macOS)**
1. Сборка карточек из фикстур.
2. Отработка отсутствующих полей.

**UI‑тесты (Playwright, macOS)**
1. Рендер плиток из `mock-data.json`.
2. Проверка hover‑стиля.
3. Проверка клика (ставится класс `is-launching`).
4. Затемнение для игры и рабочего стола нельзя закрыть на 5-й секунде и до истечения 10 секунд; после 10 секунд появляется подсказка и клик возвращает список игр.

**Windows‑специфичные ручные тесты**
1. Чтение реестра `last_server` и `auth_token`.
2. Запуск игры с рабочей директорией и аргументами.
3. Desktop закрывает лаунчер без запуска exe.
4. В release-сборке запустить установленную Steam-игру через `steam.exe` с аргументами `-applaunch <AppID>`: проверить с закрытым и уже работающим Steam. Повторить с дополнительными параметрами игры и путями в кавычках. Проверить запуск Epic URI с внешними кавычками и без них.
5. Windows-only тест `test_windows_launch_args_are_not_quoted_as_one_argument` проверяет передачу командной строки дочернему процессу без запуска Steam; фактический запуск игры требует ручной проверки.

**Критерии готовности**
- Unit и UI‑тесты проходят на macOS.
- Ручные тесты на Windows подтверждают запуск и реестр.

**Режим `--windowed` — ручная проверка на Windows**
1. При масштабировании 100%, 125% и 150% запустить лаунчер без аргументов и с `--windowed`. Без аргумента окно полноэкранное; с аргументом — без рамки, шириной 60% монитора, по центру. Разница боковых отступов допускается не более одного физического пикселя.
2. Проверить, что верх и низ окна совпадают с вертикальными границами рабочей области, панель задач не перекрыта. Повторить с панелью сверху и с автоскрытием: ориентироваться на рабочую область ОС.
3. С двумя мониторами проверить открытие на основном, в том числе при разных масштабах и смещённых координатах экранов.
4. Убедиться, что при запуске нет вспышки полноэкранного окна, рамки и возможности изменения размера.
5. Проверить карточки, фильтры, прокрутку и модальные окна на уменьшенной ширине, в том числе на экране 1366×768.
6. Свернуть окно через карточку рабочего стола и восстановить через панель задач: размер и положение должны сохраниться.
7. В `--windowed` проверить меню миниатюры панели задач и Alt+Space: «Переместить», «Размер», «Развернуть» недоступны. Win+стрелки и Win+Shift+стрелки не должны перемещать или растягивать окно; сворачивание разрешено.
8. Повторить сворачивание и восстановление несколько раз через панель задач и карточку рабочего стола при масштабировании 100%, 125% и 150%. Проверить фокусировку, клики и закрытие окна.
9. На ширинах 820 и 1152 CSS px проверить скрытие полос прокрутки страницы, длинного описания и списка фильтра при работающей прокрутке колёсиком, тачпадом и клавиатурой. Над приветствием — 18 px, включая многострочный заголовок. После перезагрузки оформление сохраняется. В полноэкранном режиме оформление прежнее.

Windows-only Rust-тест `blocks_geometry_changes_but_allows_minimize_and_restore` проверяет запрет смены геометрии через Win32, системные команды и повторное сворачивание/восстановление. Запускать `cargo test --manifest-path src-tauri/Cargo.toml` на Windows; проверка компиляции с другой ОС не заменяет выполнение этого теста.

Автоматические Rust-тесты проверяют аргумент и расчёт геометрии. Масштабирование нативного окна, панель задач и выбор монитора требуют проверки на Windows; браузерные UI-тесты их не проверяют.
